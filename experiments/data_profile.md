# Dataset Profile

This report was produced from read-only, memory-bounded scans of the supplied
TSV files. Large files were processed in chunks; no dataset was modified.

## Source-file schema

Every train and test source file has the same tab-separated schema, in this
exact order:

| Column | Stored type | Meaning observed from the data |
|---|---|---|
| `entity_id` | text | Source-specific entity identifier. |
| `business_name` | text | Business name. |
| `business_address` | text | Business address; may be blank in Sources 2 and 3. |
| `country` | text | Country value. |

The files are TSVs. Fields should be read as text rather than inferred numeric
types: names, addresses, countries, and IDs are all textual values.

## ID formats

All source-record IDs follow these formats with a numeric suffix:

| Dataset | Expected format | Invalid rows found |
|---|---|---:|
| Source 1 | `S1-<digits>` | 0 |
| Source 2 | `S2-<digits>` | 0 |
| Source 3 | `S3-<digits>` | 0 |

The ID prefix identifies the source and must be preserved exactly. It must not
be converted to an integer or regenerated by the matching pipeline.

## Train/test schema comparison

The schema and column order are identical between train and test for each
source. They are also identical across Sources 1, 2, and 3. The differences are
only the row counts, ID prefixes, values, and the observed rate of missing
addresses.

## Ground-truth structure

`train_ground_truth.tsv` has 2,206,821 data rows and exactly two text columns:

```text
source1_entity_id<TAB>matched_entity_ids
```

`source1_entity_id` contains one unique valid `S1-*` ID per row. There are no
duplicate Source-1 rows and no blank Source-1 IDs.

`matched_entity_ids` is a comma-separated list of zero or more valid IDs from
Sources 2 and 3. It is not a single label column and it is not a pair-per-row
table. A blank field represents a Source-1 entity with no labelled match.

| Ground-truth property | Value |
|---|---:|
| Rows with an empty match list | 123,247 (5.58%) |
| Non-empty labelled links | 7,638,365 |
| Links to Source 2 | 3,693,619 |
| Links to Source 3 | 3,944,746 |
| Matches per Source-1 entity | 0 to 11 |
| Mean matches per Source-1 entity, including empty lists | 3.4613 |

The match-count distribution is 0: 123,247; 1: 119,157; 2: 375,212; 3:
530,841; 4: 484,115; 5: 321,957; 6: 164,868; 7: 63,968; 8: 18,680; 9:
4,205; 10: 534; 11: 37.

Therefore, entity resolution is a one-to-zero-or-many relationship from each
Source-1 entity to candidate entities drawn from both Source 2 and Source 3.
All non-empty ground-truth match IDs follow `S2-<digits>` or `S3-<digits>`.
